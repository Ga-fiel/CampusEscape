# CampusEscape 项目基础解释

> 面向策划 / 程序员 / 架构师多 agent 共读。目标：读这一篇就懂项目现在是什么、用什么技术、代码在哪、各自从哪接手。
> 事实边界：下面写的是**当前仓库的真实状态**（截至技术切片），不是未来规划。规划见 `doc/逃学模拟器_*.md`。

---

## 1. 一句话定位

**第一人称 3D 校园逃脱游戏**：从头顶黑板的教室出发，躲开巡逻老师的视线，摸到出口逃出学校。
**最大的特色是美术**：黑板底 + 白色粉笔线稿 + 排线阴影，全部由 GPU 上的数学函数实时生成，**零图片、零模型、零音频文件**。

灵感来自一个 1.8MB 的涂鸦射击游戏（同样零素材、纯代码出画面）。本项目借它的"程序化美术"思路，换成黑板粉笔风格 + 潜行逃脱玩法。

---

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 运行形态 | 纯静态网页 | 无后端、无数据库、无登录。浏览器打开即玩 |
| 模块系统 | 原生 ES Module + importmap | `type="module"` + `import`，浏览器原生支持，**没有 webpack/vite 等构建工具** |
| 3D 引擎 | three.js r170 | 本地内置于 `vendor/three/three.module.js`（约 1.3MB，是项目体积主体） |
| 渲染 | WebGL + 自定义 GLSL 着色器 | 4 个 shader，两遍渲染，风格全靠后处理算出来 |
| 启动方式 | `python serve.py` | 一个纯静态文件服务器，默认 `http://127.0.0.1:8911`，占用则自动 +1 |
| 素材 | 无 | 几何体代码生成，画面 GLSL 生成；当前切片**尚未接入任何声音** |

**为什么这样选**：为了复刻原作"极小体积、纯代码出画面"的核心卖点。不引入素材、不引入构建链，保持项目能被直接读懂和快速迭代。

**关键约束（架构师注意）**：
- 必须用 HTTP 服务打开（`python serve.py`），**直接双击 `index.html` 会因 `file://` 的 CORS 限制导致 ES Module 加载失败**，页面外壳在但游戏跑不起来。
- three.js 版本锁定在 r170，API 若升级需同步核对。

## 4. 三个角色分别从哪接手

**程序员**：
- 主循环、输入、移动、碰撞、胜负判定全在 `src/main.js` 的 `tick()`。
- 加关卡几何 → `src/level.js` 的 `buildClassroom()`，用 `box()` 拼，需碰撞就传 `collide=true`。
- 加 NPC/敌人 → 仿 `src/teacher.js`：造型用 `makeChalkMaterial()`，`update(dt, playerPos)` 每帧被主循环调用，返回是否被发现。
- 材质只有一个入口 `makeChalkMaterial()`（在 `chalk.js`），**所有物体自动获得粉笔风格，不用单独调美术**。

**策划**：
- 当前玩法的完整愿景在 `逃学模拟器_关卡设计_v0.1.md`（10 个箱庭、怀疑值、伪装、日程驱动、多路线结局）和 `逃学模拟器_MVP框架_v0.2.md`（裁剪到"躲视线 + 拿钥匙过关"4 个系统、垂直切片）。
- 当前代码只实现了这两个设计文档里"教室序章"的最小切片，属于起点，不是成品。

**架构师**：
- 渲染管线见第 5 节；这是全项目的技术核心与性能热点。
- 模块边界清晰：`chalk.js`（渲染） ← `level.js`/`teacher.js`（内容） ← `main.js`（编排），依赖单向，无循环。

## 5. 当前已实现的功能（技术切片现状）

- 第一人称：WASD 移动、鼠标看向（Pointer Lock）、AABB 碰撞。
- 一间教室：地面/天花板/四墙/黑板/讲台/3×5 课桌/出口门框。
- 一个老师：粉笔火柴人造型，沿 4 点矩形路线往复巡逻，半角 35°、距离 9m 的视锥检测；被看到立即判负。
- 胜负：走到前墙黑板附近 = 逃出成功；被老师发现 = 被抓；按 R 重开。
- 调试模式：`index.html?shot=1` 隐藏遮罩并把 shader 错误显示到屏幕，用于无头截图验证。

**尚未实现**（属于后续目标）：钥匙/道具、盘问、警觉值、多出口、走廊/楼梯/校门等其余箱庭、音频。

## 6. 美术风格实现原理（项目核心，务必理解）

风格不在物体材质里画，而在**两遍渲染**里算：

**第一遍** `chalk.js` 的 `chalkVert`/`chalkFrag`：把整个 3D 场景渲染进一张离屏纹理（`WebGLRenderTarget`），**不输出颜色，输出数据**——
`vec4(shade, chalk, normal.x, normal.y)`：R 存明暗，BA 存世界法线。同时导出深度纹理。物体表面长什么样由 GLSL 根据法线和光照方向算。

**第二遍** `postVert`/`postFrag`：用一个铺满屏幕的 2×2 平面，对第一遍的每张像素做风格化合成，全部美术都在这里：
1. **噪声**（`hash21` 伪随机 + `vnoise` 平滑）：让线条抖动、断续，模拟手绘不规则。
2. **描边**：对"逆深度"做拉普拉斯二阶差分 + 比较相邻法线，找出物体轮廓，画成粉笔线。
3. **排线 Hatching**：按明暗程度叠加不同方向的斜线，越暗线越密，表现阴影。
4. **黑板底 + 颗粒 + 暗角**：深墨绿底、擦痕、噪声颗粒，整体压暗。

关键代码位置：`src/chalk.js` 的 `postFrag`（第 43–140 行）是风格总开关，`ChalkRenderer.render()`（第 195 行）执行两遍流程。

**排错经验**：`vnoise` 里曾把 `vec2` 赋给 `vec4` 导致 GLSL 编译失败（dimension mismatch）；改色调整体在 `postFrag` 末尾的合成段调。

## 8. 扩展方向（给后续迭代）

1. **按 MVP 文档补核心系统**：警觉值（一个 float）、钥匙道具（一个 bool 集合）、盘问（一次判定）——都是轻量改动，接口已留。
2. **按关卡文档扩箱庭**：走廊 → 楼梯 → 校门，其余 NPC 复制 `Teacher` 模式。
3. **音频**：当前完全没有，若要做需新增合成音效模块（原作是 WebAudio 合成，零音频文件）。
4. **美术微调**：全部集中在 `postFrag`，改风格不碰玩法代码；反之亦然。
