# 《逃学模拟器》MVP 框架 v0.2

> 目标：第一个项目能跑通。**机制少、代码少、但玩家能感觉到"有条条大路通校门"。**
> 原则：不做 10 个机制，做 1 个机制 + 10 种包装。

---

## 0. 一句话

**一个核心循环（躲视线 + 拿东西过关）＋ 一张地图 ＋ 多把钥匙 ＋ 多个出口。**
玩家自由决定先找哪把钥匙、走哪个出口。

---

## 1. 先决定"砍什么"

| 砍掉 | 原因 | 以后要吗 |
|---|---|---|
| 分心 / 丢石头 | 多一套 AI，收益低 | 不要 |
| 听觉 / 声音掩蔽 | 要音频系统 + 触发链 | v0.4 再说 |
| NPC 记忆（第二次起疑） | 要状态存档 | 可选 |
| 动态作息表 | 要全局时钟 + 各系统联动 | 以后 |
| 伪装多状态互斥 | 状态机膨胀 | 砍，改成"道具 bool" |
| 凭证链交叉验证 | 逻辑分支爆炸 | 砍，改成"单点判定" |
| 摄像头断电解谜 | 独立小系统 | v0.3 |
| 攀爬物理 | 要动画 + 碰撞调参 | 用"钥匙"代替 |

**保留的只有 4 个系统。**

---

## 2. 四个核心系统

### 2.1 视野（唯一的潜行系统）

```
NPC 每帧检测：
  距离 < 视野半径
  且 角度 < 视野角
  且 射线没被 "掩体" 挡住
  → 看见玩家
```

- 玩家 3 种状态：**站 / 蹲 / 跑**（只影响被发现距离，不做别的）
- 掩体 = 打了 `Cover` 标签的碰撞体（垃圾桶、门框、宣传栏、柱子）
- **代码量：一个 Raycast + 一个角度点乘**

> 这就是全部潜行。所有关卡都靠它，不新增。

### 2.2 警觉值（唯一的数值）

| 事件 | 变化 |
|---|---|
| 被看见（站/跑） | +25 / 秒 |
| 被看见（蹲） | +8 / 秒 |
| 躲在掩体后 | −15 / 秒 |
| 被盘问失败 | +30（一次性） |
| 满 100 | **被抓住** |

- 不做分档、不做 UI 花哨，就是一条会涨会掉的条。
- **代码量：一个 float + 每帧加减。**

### 2.3 钥匙道具（唯一的进度系统）

- 每个道具就是一个 `bool`：`has_test_paper`、`has_pliers`、`has_leave_note`……
- 道具只做两件事：**开一扇门** 或 **过一次盘问**。
- **代码量：一个 HashSet。**

### 2.4 盘问（唯一的对话）

不做多轮对话，就一次判定：

```
遇到 NPC 拦路：
  if 持有该 NPC 认可的钥匙 → 通过
  else → 警觉 +30，NPC 继续拦你
```

- 每个 NPC 只认 1 个道具（主任认试卷、门卫认请假条、狗洞认钳子）。
- **代码量：一个 if。**

## 3. 多通关方式 = 钥匙-锁（核心创新）

**一张地图，N 把钥匙，M 个出口，玩家自己选顺序。**

| 出口 | 需要的钥匙 | 钥匙藏在哪 | 硬核度 | 玩家感受 |
|---|---|---|---|---|
| **正门** | 请假条 | 教师办公室 | ★ | “我是合法走的” |
| **狗洞** | 钳子 | 体育器材室 | ★★★★ | “我把学校钻穿了” |
| **翻墙** | 垫脚箱（垃圾桶） | 后墙边 | ★★★ | “我爬出去的” |
| **后门** | 后门钥匙 | 食堂阿姨 | ★★ | “阿姨放我走的” |
| **混放学** | 等到放学（时间） | —— | ★ | “我就跟着人流走了” |

设计要点：

- **每把钥匙都在不同箱庭**，玩家为了找钥匙自然会把学校逛遍。
- **拿到任意一把 + 走到对应出口 = 通关**。没有强制顺序。
- 钥匙不是"任务奖励"，是"世界里的物件"——钳子就在器材室地上，请假条就在办公桌上。

> 这就实现了你要的"不被失败前提下尽情探索不同的过关方式"：
> 玩家在找一个出口，半路发现另一把钥匙，就会想"我试试这条路"。

## 4. 概率机制（第二层，先留接口）

你说"靠概率有创新点"，我建议这样用，**风险可控、代码极简**：

### 伪装识破率

```
持有试卷遇到主任：
  基础成功率 70%
  + 再拿一本作业本     +15%
  + 校服穿整齐          +10%
  上限 95%
  掷骰子：成功 → 放行；失败 → 警觉 +30（不直接抓）
```

- **失败只是涨警觉，不是失败**——给玩家一次补救机会。
- 概率是"可以投资的"：多找一个道具，风险就低一分。玩家会觉得"我是在管理风险"，不是"我在赌"。
- **代码量：一个 `Random.value < rate`。**

### 翻墙成功率（硬核线的赌点）

```
没找到垫脚箱直接翻：60% 成功
找到垫脚箱：100%
失败 → 掉下来 + 警觉 +40（引来保安）
```

- 这条是给"我就想赌一把"的玩家的。**赌输了也不 Game Over，只是变难。**

> MVP 里先把成功率写死 100%，流程跑通后再调参数。接口留好就行。

---

## 5. 失败 = 传送，不是 Game Over

这是"尽情探索"的关键。

```
被抓：
  1. 短暂演出（主任拎耳朵 / 罚站）
  2. 传送到最近检查点
  3. 道具全部保留、已开的门保持打开
  4. 警觉值清零
```

- **没有死亡、没有读档、没有惩罚**。
- 被抓一次 = 多知道一条巡逻路线，反而有收获。
- 甚至可以做：被抓时主任会说一句"你刚才想干嘛？"——**失败也是信息**。

> 玩家敢乱试，是因为试错成本几乎为零。

## 6. MVP 范围：先做一个"垂直切片"

**只做 1 个箱庭 + 2 个出口，10 分钟通关。**

```
教室 → 走廊（1 个主任巡逻）→ 楼梯 → 校门广场
                                      ├─ 正门（要请假条）
                                      └─ 狗洞（要钳子）
```

| 内容 | 数量 |
|---|---|
| 场景 | 走廊 + 楼梯 + 校门广场 |
| NPC | 教导主任 ×1（一条巡逻路线） |
| 道具 | 试卷、请假条、钳子 |
| 出口 | 2 个 |
| 检查点 | 2 个（厕所、楼梯口） |
| 时长 | 8–12 分钟 |

**验收标准**：
- 玩家能靠"躲 + 拿东西"通关；
- 玩家能发现两条不同路线；
- 被抓后能自己走回来，不烦躁。

**这一个切片做出来，整个游戏就成立了。** 后面所有关卡都是它的加料。

## 7. 代码骨架（引擎无关伪代码）

```text
// NPC 状态机 —— 只有 3 个状态
enum State { Patrol, Alert, Catch }

Update():
  if canSeePlayer():
      alert += rate
      if alert >= 100: state = Catch
      else: state = Alert      // 走向玩家
  else:
      alert -= decay
      state = Patrol           // 回巡逻路线

// 视野检测
canSeePlayer():
  if dist > viewRange: return false
  if dot(forward, dirToPlayer) < cos(viewAngle/2): return false
  if Physics.Raycast(eye, dirToPlayer, "Cover"): return false
  return true

// 盘问
OnIntercept(npc):
  if player.Has(npc.requiredItem):
      if Random.value < npc.successRate: npc.LetPass()
      else: alert += 30
  else: alert += 30

// 出口
OnExit(exit):
  if exit.requiredItem == null or player.Has(exit.requiredItem):
      Win()
  else:
      ShowHint("这里需要：" + exit.requiredName)
```

**总计不到 100 行核心逻辑。**

## 9. 关于"玩法重复"的节奏建议

你说得对，躲视线重复没问题。但要注意**频率和包装**：

| 做法 | 效果 |
|---|---|
| 同一机制，换场景换皮 | 玩家觉得"新关卡"，你不加系统 |
| 每个箱庭只加 1 个"小变体" | 如走廊加"试卷伪装"、操场加"贴人群" |
| 重复的关卡放在两侧，新机制放中间 | 紧张-喘息-紧张的节奏 |
| 连续 3 个箱庭用同一机制 → 必换 | 否则腻 |

**核心动词只有 2 个：`躲` 和 `拿东西过关`。**
所有箱庭都是这两个的变奏。这就是第一个项目该有的规模。
