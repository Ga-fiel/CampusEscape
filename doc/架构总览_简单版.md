# CampusEscape 架构总览（v2·简单版）

> 目标：多个**场景(scene)**，一个场景可以是一整层楼（箱庭），也可以是半层/几间房，**大小由你定**。
> 每个场景一个文件夹，可复用资源/敌人放公共层，main 负责加载场景和切换。
> 原则：**够用就好，别抽象**。全部原生 ESM + importmap，无构建工具，three r170。

---

## 术语（一句话）

- **场景(scene)**：一次加载的整张世界，一个文件夹。
- **房间(room)**：场景内部的一块矩形空间，多个房间拼成一个箱庭，靠**门**连通。
- **箱庭(sandbox)**：就是「多房间拼成的场景」这种形态。场景多大你说了算。

## 目录结构

```
CampusEscape/src/
├── main.js                 【入口】组装引擎/物品栏/场景管理器，主循环，UI，输入，怀疑度
│
├── chalk.js                【渲染】粉笔两遍渲染（项目核心，不碰）
│
├── game/
│   └── inventory.js        【物品栏】跨场景携带的拾取物（一个字符串集合）
│
├── reusable/               【可复用层】哪个场景都能用的东西
│   ├── enemy-base.js       PatrolEnemy —— 可复用敌人 AI（巡逻/回头/视锥/追逐/造型）
│   ├── resources.js        placePrefab —— 摆可复用资源模型（课桌/椅/书/门…）
│   └── pickup.js           makePickup —— 可拾取物（进物品栏）
│
├── scenes/                 【场景层】
│   ├── scene-base.js       SceneBase 契约 + buildRoomShell 单房间外壳 + WorldBuilder 箱庭工具
│   ├── scene-manager.js    SceneManager —— 加载/切换场景、拾取/交互/出口检测、敌人更新
│   ├── registry.js         场景 id → 场景对象 的登记表
│   └── floor3/             【场景】三楼（整个一层楼）
│       └── index.js        floor3（ROOMS 六个房间 + DOORS 门洞 + 教室布置）
│
├── scene/                  【场景数据/构建基础设施】（被场景与编辑器共用）
│   ├── scene-data.js       教室的空间数据（SCENE + DESK_GRID）
│   ├── schema.js           场景 JSON 格式契约 + 归一化
│   ├── scene-build.js      数据→three 物体，PREFABS 零件库
│   └── serialize.js        场景树→JSON（编辑器用）
│
└── tool/                   通用场景编辑器（与游戏逻辑无关）
```

> 注：`src/level.js` 是编辑器 `src/tool/editor-ui.js` 依赖的旧文件（提供 `getFullSceneData`），保留。

## 数据流 / 依赖方向（单向）

```
chalk.js  ← 所有人用（材质+渲染）

reusable/*  ← 场景用（敌人/资源/拾取）
scene/*     ← 场景用（构建基础设施）
game/inventory ← main 用

scenes/<场景>/index.js  ← 用 reusable + scene + scene-base
scenes/scene-manager    ← 调度场景
scenes/registry         ← 登记所有场景

main.js  ← 组装以上一切，只做「编排」，不写具体场景内容
```

**规则：下层不 import 上层。场景不 import main。**

## 一个场景从加载到发生什么

```
main.loadScene(id)
  → SceneManager.load(id): 卸载旧场景 → getScene(id) → scene.build(ctx) 生成几何/房间/门/敌人/出口
  → main 把玩家放到该场景 spawn

每帧 tick():
  → SM.update() 更新本场景所有敌人(seen/arrived) + 拾取物动画
  → 玩家 WASD 移动；若场景有 bounds（箱庭多房间），用 moveWithBounds 逐轴滑动 + 撞墙推出
  → 靠近门按 F：SM.interactAt() 命中 → 若返回 walkThrough 则平滑过门
  → 走到出口触发区 → SM.exitAt() 命中 → SM.goThroughExit() 切到 target 场景（或通关）
  → 按 E：优先 exitAt 切场景，其次 pickupAt 捡东西进 inventory
  → 敌人 seen 累积怀疑度，满 100 判负，敌人 startChase 演出
```

**物品栏跨场景：** 整个游戏只有一份 `Inventory`，切场景不重建，所以捡到的东西天然带到下一个场景。
**箱庭房间互通：** 房间之间靠门洞直接连通，玩家走过去即可，不需要「出口」。

## 「以后要加什么，在哪里写」速查表

| 我要加… | 写在哪 | 怎么做 |
|---|---|---|
| **一个新场景** | `src/scenes/<id>/index.js` + `registry.js` | 见 `doc/如何新增场景.md` |
| **某个场景里加/改房间** | 该场景 `index.js` 顶部的 `ROOMS` | 加一项 `{id,minX,maxX,minZ,maxZ}` |
| **房间之间开门洞** | 该场景 `index.js` 的 `DOORS` | 加一项 `{room,wall,at,width}` |
| **一扇可交互的门（按F推开）** | 该场景 `index.js` 往 `this.interactables` push | `{id,name,pos,radius,interact()}` |
| **新的可复用敌人外观** | `src/reusable/enemy-base.js` | 派生 `PatrolEnemy` 或加造型分支 |
| **新的可复用模型**（桌椅柜…） | `src/scene/scene-build.js` 的 `PREFABS` + `placePrefab` 调用 | 写个生成函数返回 Object3D |
| **新的可拾取物外观** | `src/reusable/pickup.js` 的 `SHAPES` | 加一个 shape 函数 |
| **某场景独有的机关/装饰** | 该场景 `resources.js` 或 `index.js` 里 `helpers.box` | 只作用于该场景 |
| **改教室桌椅布局** | `src/scene/scene-data.js` | 改坐标/数据 |
| **改敌人巡逻路线/视野** | 该场景 `index.js` 里 `PatrolEnemy({...})` 配置 | 改 patrolPoints/viewDist 等 |
| **改场景出口/需求道具** | 该场景 `index.js` 的 `this.exits.push({...})` | 改 target/require/contains |
| **改初始加载场景（调试）** | `src/main.js` 的 `INITIAL_SCENE` 或 URL `?scene=` | — |
| **改玩家速度/眼高/怀疑度规则** | `src/main.js` 顶部常量 | — |
| **改美术风格** | `src/chalk.js` 的 `postFrag` | — |

## 常用 API 速记

- **SceneBase**：`build(ctx)`（必须）、`getHelpers(ctx)→{mat,box,add}`、字段见「如何新增场景」第 6 节。
- **WorldBuilder**(level, helpers, {rooms, doors, height})：`buildAll()` = 地面 + 外墙(门洞开/门楣补) + 交付 `bounds`。
- **buildRoomShell**(level, helpers, room)：单矩形房间四面墙+地+顶（简单单房间场景用）。
- **SceneManager**：`load(id)` / `spawn()` / `pickupAt(pos)` / `interactAt(pos)` / `exitAt(pos)` / `goThroughExit(exit)` / `update(dt,pos,h)`。
- **PatrolEnemy**(parent, config)：可复用敌人。
- **placePrefab**(level, name, opts) / **makePickup**(level, opts)：可复用资源 / 拾取物。
